POSMaster V3

An Electron point-of-sale terminal for a Sri Lankan tea cooperative — three processes, one strict IPC boundary, and a Mongo-backed event log that pushes every change back to the till in real time.

Topology

The whole system on one page

The renderer never touches the network. Every read and write leaves the UI through a single contextBridge namespace, crosses into the main process, and only there becomes HTTP. That's enforced by absence — a grep for fetch(, axios or port 4100 across all 116 renderer files returns nothing.

Runtimes

The same code ships as two topologies

In development the online server is a separate node process you start yourself. Once packaged, runtime.cjs is required into the Electron main process — Express, Socket.IO and the Mongo driver all run inside the desktop app, and "online" becomes a loopback call to itself. No external server exists.

Consequence

There is no requestSingleInstanceLock anywhere in the repo. Two packaged copies can run at once, and the second one's attempt to bind :4100 fails into a swallowed try/catch — leaving an app that looks fine but whose writes land through the first instance's server.

Write path

How a sale reaches the database

Eight hops from a cashier's tap to a committed transaction, crossing four process zones. Each boundary is a place the call changes character — from a function call, to IPC, to HTTP, to a wire protocol.

Read path

How the change comes back

The return trip is not a response to the request that caused it. Every mutation is persisted to domain_events, then fanned out over Socket.IO — so a sale rung up on one till updates stock on every other till in the branch, including the one that rang it.

Identity

Auth is two factors, and one of them is a row

A valid signature is not enough. requireAuth verifies the JWT and then looks up a matching sessions document with active: true. The raw token is never stored — only its SHA-256 hash — so the database can revoke a session it cannot read.

State

Two machines worth knowing by heart

Most of this system is CRUD. These two aren't — they're the places where an object's history matters, and where a wrong transition means stock that exists in the database but not on a shelf.

Branch-to-branch transfer · two-stage approval

A transfer is reviewed twice: once by the source branch's manager, then again by the receiving branch. Crucially, no stock moves until the second accept — the first is a paperwork gate.

Inventory unit lifecycle

Individually tracked units carry a state, and every transition writes a matching row to stock_movements. The movement type is the edge label.

Printing

Two mechanisms, and a default resolved in the wrong place

POS_RECEIPT_PRINTER_MODE picks between raw ESC/POS over TCP and the OS print queue. The default is auto — and the main process, which owns both mechanisms, doesn't resolve it. It only reports the mode; SalesView.jsx decides.

Two zeros worth explaining

audit_events is indexed on every connect and written by nothing — it's dead. tea_coop_sync_runs is at zero for a subtler reason: the sync-run row is only written on success, and a failure throws before reaching it. Failed syncs leave no trace at all.

Findings

Things worth knowing before you change anything

Surfaced while mapping the system. Ordered by how much they'd cost you to discover the hard way.

SecurityOnlineModeService.cjs · preload.cjs:28

Two holes in the boundary the rest of the design depends on. Path B runs Mongo aggregations straight from the main process with no auth check, scoped only by a default org id. And invoke/send are exposed on the contextBridge as unrestricted passthroughs to any channel — the careful per-namespace API surface sits right next to a wildcard.

Dead pathelectron.cjs:1009 · createWindow()

Logout-on-close never fires. The close handler that calls it lives inside createWindow(), which startup never calls — the real window is built inline at line 1255 and gets no listener. The AppSettings toggle persists a setting no main-process code reads.

Silent wrong answerOnlineController.cjs:161–225

Several legacy compat shims accept arguments and discard them. categories:search, users:search, restocks:get-by-date-range and stock:get-low-stock all return the unfiltered full list. They don't error — they answer a different question than the one asked.

ScaleteaCoopSyncService.cjs:268

Members sync requests page=1&limit=100 with no pagination loop. There are 5,152 members in the collection today, so a full sync silently covers about 2% of them.

Cleanuputils/eventBroadcaster.cjs · frontend/renderer/ · hooks/useDataChangeListener.js

Confirmed dead: a 270-line event broadcaster with zero requires, a renderer/ directory containing nothing but three .DS_Store files, an unused data-change hook, two fully commented-out bill components, and audit_events. unregisterAllHandlers() logs and returns without removing a single handler.
